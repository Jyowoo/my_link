# 마이링크 PRD · 테스트 페이지 기능 정의서

버전: 1.12 | 수정일: 2026-10-03 | 용도: 팀 개발 포트폴리오용 프런트엔드 시제품

이 버전은 기존 서비스 MVP 명세를 대체한다. 현재 목표는 프로필·링크를 직접 수정하고 테마를 바꾸는 경험을 테스트하는 것이다. **확정**은 사용자가 지정한 방향이고, **제안**은 구현을 위한 기본 정책이다. 로그인과 외부 DB 연동은 필요하지 않다.

**현재 구현과 목표 구분:** 현재 프로젝트는 정적 개발자 프로필 페이지(`/`)와 로컬 상태 기반 링크 목록·추가 페이지(`/links`)다. 아래 제품 흐름·화면·F01~F08·인수 테스트는 앞으로 구현할 목표이며, 완료 상태는 2장의 현황과 6장의 기술 목록을 기준으로 판단한다. 기술 현황은 `package.json`, `package-lock.json`, 설정 파일과 `src/`의 실제 사용 코드를 대조했다.

## 1. 제품 목표

마이링크는 일반 개인이 사진, 이름, 소개글과 SNS·작업물 링크를 한 화면에 정리하는 자기소개 페이지다. 첫 버전에서는 편집과 미리보기의 사용성을 검증한다. 기본 기능을 무료로 충분히 제공한다는 방향을 유지한다.

목표 버전에서는 사용자가 페이지에 접속하면 바로 예시 프로필을 편집할 수 있어야 한다. 수정 사항은 미리보기에 즉시 반영되고 같은 브라우저에 자동 저장되도록 구현한다. 실제 사용자별 공개 페이지 발행은 후속 작업으로 남긴다.

### 링크 목록 페이지 — 구현 완료

- 경로는 `/links`이며 기존 프로필 상단의 “링크 모음 보기”로 이동한다. 목록 페이지에는 프로필로 돌아가는 링크를 제공한다.
- `src/data/demo-links.json`을 `displayOrder` 오름차순으로 표시한다. 제목·설명·분류·동작 문구·아이콘·선택적 배지를 보여주며 ID를 목록 키로 사용한다.
- shadcn/ui Card·Badge·Button과 Tailwind CSS·Lucide 아이콘을 사용하며 모바일·PC에 맞춰 여백과 줄바꿈을 구성한다.
- 외부 링크는 새 탭으로 열고 `noopener noreferrer`를 적용한다. 보조 기술에 새 탭 열기를 안내하고 키보드 포커스를 표시한다.
- 더미 데이터의 `Instagram` 아이콘 이름은 현재 Lucide 버전의 지원 아이콘인 `MessageCircle`로 매핑한다. 알 수 없는 아이콘은 `Link2`, 미등록 분류는 원래 식별자로 표시한다.
- 배지가 `null`이면 생략하며 링크가 없으면 빈 목록 안내를 표시한다. 예시 주소라는 안내를 제공한다.
- 링크 목록 표시·다이얼로그 추가는 완료했다. 수정·삭제·영속 저장·테마 선택·보기 모드 전환은 구현 예정이다.

페이지의 기술 스택 칩은 프로필 소개 문구다. 여기에 표시된 Node.js·Git 등을 별도의 설치 라이브러리나 제품 기능으로 판단하지 않는다.

## 3. 기본 사용자 흐름 — 구현 예정

1. 처음 접속하면 예시 프로필·링크와 기본 테마가 표시된다.
2. 사용자는 이름·소개·사진을 수정하고 링크를 추가하거나 편집한다.
3. 미리보기에서 수정 결과를 즉시 확인한다.
4. 테마를 선택하면 미리보기 전체에 적용된다.
5. 유효한 변경 사항이 브라우저에 자동 저장된다.
6. 보기 모드에서 편집 도구 없이 결과를 확인한다.
7. 다시 접속하면 마지막 저장 데이터가 복원된다.

편집 데이터와 공개 데이터는 이번 버전에서 구분하지 않는다. 게시 버튼과 사용자 주소 선택 화면도 만들지 않는다.

## 4. 화면 구성 — 구현 예정

| 화면·영역 | 구성 | 주요 동작 |
| --- | --- | --- |
| 상단 | 서비스명, 편집·보기 모드 전환, 저장 상태 | 현재 모드와 저장 성공·실패 확인 |
| 프로필 편집 | 사진, 이름, 소개글 | 입력·사진 선택·사진 제거 |
| 링크 편집 | 링크 목록, 제목·URL 입력, 추가·수정·삭제, 위·아래 이동 | 링크와 순서 관리 |
| 테마 선택 | 기본 테마 3개, 선택 상태 | 테마 적용 |
| 미리보기 | 사진, 이름, 소개글, 링크 버튼 | 입력 결과 즉시 확인 |
| 보기 모드 | 편집 도구가 없는 프로필 화면, 편집으로 돌아가기 | 링크 이동·화면 확인 |
| 데이터 초기화 | 예시로 초기화 버튼, 확인 대화상자 | 현재 브라우저 데이터를 예시로 교체 |

PC에서는 편집 패널과 미리보기를 함께 보여준다. 모바일에서는 편집·미리보기 전환을 제공한다. 보기 모드는 같은 앱 안의 화면 상태이며 별도 공유 페이지가 아니다.

## 5. 기능 명세

아래 숫자와 동작 세부사항은 **제안**이다. 첫 버전 필수 기능을 P0으로 정의한다. F01은 링크 더미 데이터와 `/links` 표시까지 준비됐으며 초기화·복원 기능은 미구현이다. F03은 로컬 상태 기반 링크 추가만 구현 완료했다. 수정·삭제·영속 저장과 나머지 기능은 구현 예정이며 전체 F03 완료로 보지 않는다.

### F01. 초기 데이터·복원 — P0

- 저장 데이터가 없으면 샘플 이름, 소개글, 기본 아바타, 예시 링크 3개와 미니멀 테마를 표시한다.
- 예시 데이터와 테마 설정은 한곳에서 관리해 쉽게 교체할 수 있게 한다.
- 링크 목록용 더미 데이터 3개를 `src/data/demo-links.json`에 작성했다. 포트폴리오·블로그·SNS 예시이며 `id`, `title`, `description`, `url`, `icon`, `category`, `actionText`, `isExternal`, `badge`, `displayOrder`의 10개 필드를 사용한다.
- 더미 URL은 `https://example.com`의 예시 경로로 작성하며 실제 개인 계정이나 콘텐츠 주소가 아니다. 현재 `/links` 페이지에 연결했다. 최초 접속 편집 데이터·예시 초기화 시 적용은 후속 구현에서 진행한다.
- 저장 데이터가 있으면 검증 후 복원한다. 유효하지 않은 필드에는 기본값을 적용한다.
- JSON 파싱 실패 등으로 복원이 불가능하면 예시 화면과 “저장된 데이터를 읽지 못했어요.” 안내를 표시한다. 실패한 원본을 자동으로 덮어쓰지 않는다.
- 복원 오류 시 저장을 일시 중단하고, 사용자가 확인 후 초기화하면 정상 저장을 재개한다.

**완료 기준:** 첫 접속과 재접속이 구분되며 잘못된 저장 데이터 때문에 빈 화면이나 앱 중단이 발생하지 않는다.

### F02. 프로필 수정 — P0

| 항목 | 입력 규칙 | 표시 규칙 |
| --- | --- | --- |
| 이름 | 최대 30자, 빈 값 허용 | 비어 있으면 “이름을 입력해주세요” 표시 |
| 소개글 | 최대 200자, 줄바꿈 허용, 선택 | 비어 있으면 해당 영역 생략 |
| 사진 | JPG·PNG·WebP, 원본 최대 5MB, 선택 | 중앙 정사각형 기준으로 표시, 미선택·삭제 시 기본 아바타 |

- 글자 수는 사용자에게 보이는 문자 단위로 계산하며 입력란에 현재 글자 수를 표시한다.
- 이름·소개는 일반 텍스트로 렌더링한다. HTML과 스크립트는 실행하지 않는다.
- 사진은 파일을 브라우저에서 읽어 표시하고 서버에 업로드하지 않는다.
- 저장용 사진은 최대 256×256px, 200KB 이하로 변환해 data URL로 보관한다. 이 처리와 크기 설정은 별도 이미지 처리 함수에 둔다.
- 형식·디코딩·크기 변환 실패 시 기존 사진을 유지하고 오류를 안내한다. 변환 후 제한을 충족하지 못한 사진도 적용하지 않는다.
- 자유로운 사진 자르기 도구는 이번 범위에서 제외한다.

**완료 기준:** 입력이 즉시 미리보기에 반영되고 사진 변경·제거 후 새로고침해도 마지막 저장 상태가 유지된다.

### F03. 링크 추가·수정·삭제 — P0

| 항목 | 규칙 |
| --- | --- |
| 제목 | 앞뒤 공백 제거 후 1~50자, 필수 |
| URL | 앞뒤 공백 제거 후 최대 2,048자, 유효한 `https://`·`http://` 절대 주소, 필수 |
| ID | 생성 시 고유 식별자 부여, 제목·URL 수정 시 유지 |
| 순서 | `displayOrder` 오름차순 기준, 새 링크는 맨 끝에 추가; 정렬 변경 시 배열과 순서 값을 함께 갱신 |

#### 링크 데이터 구조 — 확정

| 필드 | 타입 | 의미·예시 |
| --- | --- | --- |
| `id` | string | 고유 식별자, 내용·순서 변경 시 유지 |
| `title` | string | 링크 제목 |
| `description` | string | 링크 설명, 설명이 없으면 빈 문자열 |
| `url` | string | 이동할 HTTP·HTTPS 절대 주소 |
| `icon` | string | Lucide 아이콘 이름, 현재 예시는 `FolderOpen`·`BookOpen`·`Instagram` |
| `category` | string | 분류 식별자, 현재 예시는 `portfolio`·`blog`·`social` |
| `actionText` | string | 이동 동작 문구, 예: “작업 보기” |
| `isExternal` | boolean | 외부 링크 여부, 현재 더미는 모두 `true` |
| `badge` | string 또는 null | 강조 문구, 예: “추천”·“NEW”; 없으면 `null` |
| `displayOrder` | number | 1부터 시작하는 표시 순서, 목록 내 중복 없이 유지 |

아이콘은 JSON에 컴포넌트 대신 이름으로 저장하고, 화면 구현 시 허용된 Lucide 아이콘 매핑으로 렌더링한다. 분류·설명·동작 문구·배지의 편집 UI 세부 정책은 후속 구현에서 정한다. `isExternal`은 외부 여부를 나타내며 F03의 새 탭 열기 정책은 유지한다.

- “링크 추가”를 누르면 제목·URL 폼을 제공한다. 확인 시 검증을 통과한 링크만 목록에 추가한다.
- 수정도 별도 폼에서 확인한 뒤 목록에 반영한다. 미완성 폼은 미리보기와 저장 데이터에 포함하지 않는다.
- 취소하면 기존 링크를 유지한다. 미완성 입력이 있는 상태에서 보기 모드나 초기화로 이동할 때는 입력을 버릴지 확인한다.
- 삭제 시 확인 대화상자를 제공한다. 취소하면 유지하고 확인하면 삭제한다.
- 링크 개수에 제품상 상한을 두지 않는다. 브라우저 저장 용량에 따른 실패는 별도로 안내한다.
- 같은 URL의 반복 등록을 허용한다. 제목 없는 링크는 저장할 수 없다.
- URL 형식만 검증한다. 대상 사이트의 접속 가능 여부는 검사하지 않는다.
- `javascript:`, `data:` 등 다른 스킴은 거절한다. 이메일·전화 전용 링크는 후속 범위다.
- 미리보기·보기 모드에서 링크를 누르면 새 탭으로 열고 `noopener noreferrer`를 적용한다.

**완료 기준:** 유효한 링크의 추가·수정·삭제가 미리보기와 저장에 반영되며 잘못된 입력은 해당 필드에 오류를 표시한다.

#### 링크 추가 다이얼로그 — 로컬 상태 구현 완료

- `/links`의 “링크 추가” 버튼에서 shadcn/ui Dialog를 연다. 제목·URL은 필수이며 설명·분류·동작 문구·배지는 선택 또는 기본값을 제공한다.
- 제목은 앞뒤 공백 제거 후 사용자에게 보이는 문자 기준 1~50자, URL은 앞뒤 공백 제거 후 최대 2,048자의 HTTP·HTTPS 절대 주소로 검증한다. 오류는 해당 필드 아래에 표시하고 첫 오류 입력에 포커스를 이동한다.
- URL은 `https://`·`http://` 선택과 주소 입력을 분리하며 기본값은 `https://`다. 도메인·경로만 입력하면 선택한 프로토콜을 결합한다. HTTP·HTTPS 전체 URL을 입력하거나 붙여넣으면 프로토콜을 자동 선택하고 주소 부분만 입력란에 표시한다. 재개방 시 HTTPS·빈 주소로 초기화하며, 완성된 URL을 기존 규칙으로 검증한다. 다른 스킴은 계속 거절한다. Chrome 자동검증에서 전체 HTTPS 주소 자동 분리·기본 HTTPS 및 재개방 초기화·주소만 입력 후 HTTP 선택과 최종 URL 결합을 확인했으며 린트·빌드도 통과했다.
- 분류는 작업물·기록·일상·기타를 제공한다. 아이콘은 분류에 따라 설정하며, 비어 있는 동작 문구는 “링크 열기”, 배지는 `null`, 외부 여부는 `true`로 설정한다.
- 추가 시 `crypto.randomUUID()`로 ID를 생성하고 기존 최대 `displayOrder` 다음 번호로 목록 끝에 추가한다. 중복 URL은 허용한다.
- 추가 성공 시 다이얼로그를 닫고 링크 개수·목록을 즉시 갱신한다. 취소·닫기·Escape는 목록을 변경하지 않으며 재개방 시 입력을 초기화한다. Radix Dialog의 포커스 관리와 키보드 조작을 사용한다.
- 사용자의 이번 요청에 따라 데이터는 React 로컬 상태에서만 유지한다. 서버 요청과 localStorage 저장은 하지 않으며 새로고침·전체 페이지 재접속 시 추가한 링크가 사라진다. 앱 내부 `/` ↔ `/links` 이동 시에는 공유 상태를 유지한다. 목록과 폼에 이 제한을 안내한다. F06 자동 저장은 후속 요구사항으로 유지한다.
- 페이지는 메타데이터를 제공하는 서버 컴포넌트, `LinksList`는 공유 상태를 사용하는 클라이언트 컴포넌트, `AddLinkDialog`는 입력 폼으로 분리했다. 검증·데이터 타입은 `src/lib/links.ts`에서 관리한다.
- 검증 결과: 린트·프로덕션 빌드 통과, 개발 서버 `/links` HTTP 200 확인, 제목 공백·50자 경계·이모지 문자 수·HTTP/HTTPS 허용·잘못된 URL·다른 스킴·URL 길이 초과 검증 통과. Chrome 자동검증으로 다이얼로그 열기·초기 포커스·필수 입력 오류·악성 URL 거절·정상 추가·설명/동작 문구/배지 표시·목록 끝 추가·외부 링크 속성·Escape 및 포커스 복귀·취소·재개방 입력 초기화·새로고침 로컬 상태 초기화를 확인했다. 390×844 모바일 화면에서도 추가 성공·가로 넘침 없음·런타임 예외 없음으로 통과했다.

- 재실행 가능한 브라우저 검증은 `scripts/verify-link-dialog.mjs`에 작성했다. Windows의 Node.js·Chrome과 `http://localhost:3000/links` 개발 서버가 필요하며, 프로젝트 루트에서 `node scripts/verify-link-dialog.mjs`로 실행한다. 별도 테스트 라이브러리 설치 없이 Chrome DevTools Protocol로 실제 클릭·입력 이벤트를 전송한다. 검증 브라우저는 전용 프로필을 사용하고 종료한다.

#### 프로필 링크 목록 연결 — 구현 완료

- 루트 레이아웃의 `LinksProvider`에서 React Context·useState로 링크 목록을 공유한다. `/links`에서 추가한 링크는 프로필(`/`)의 “더 알아보기”에도 표시된다.
- 기존 “준비 중” 항목 2개를 공유 링크 목록으로 교체했다. 기본 더미 3개와 새로 추가한 링크가 같은 순서로 표시되며, `LinkCard`를 재사용해 제목·설명·아이콘·분류·배지·동작 문구·외부 링크 속성을 일치시킨다.
- `ProfileLinks`는 공유 상태를 읽는 클라이언트 컴포넌트다. Next.js Link로 프로필과 목록을 왕복하면 상태를 유지하며, 서버·localStorage 저장은 사용하지 않는다. 새로고침하면 기본 더미 데이터로 복원된다. Chrome 자동검증에서 추가 후 프로필 표시·목록 왕복 상태 유지·외부 링크 속성을 확인했고 기존 추가·취소·초기화·모바일 검사도 통과했다.

### F04. 링크 순서 변경 — P0 제안

- 각 링크에 위로·아래로 이동 버튼을 제공한다. 키보드·마우스·터치로 조작할 수 있다.
- 첫 링크의 위로 이동, 마지막 링크의 아래로 이동은 비활성화한다.
- 변경 즉시 미리보기와 저장 데이터에 반영한다.
- 드래그 정렬은 추후 같은 순서 변경 동작을 호출하도록 추가한다.

**완료 기준:** 변경한 순서가 보기 모드와 재접속 후에도 유지된다.

### F05. 테마 변경 — P0

- 미니멀, 소프트, 다크 테마 3개를 제공한다.
- 테마는 배경색, 이름·소개 글자색, 버튼색·글자색·모서리·간격의 사전 정의된 조합이다.
- 테마 선택 시 프로필·링크 데이터는 유지하고 시각 스타일만 바뀐다.
- 선택한 테마를 구분해 표시하며 새로고침 후에도 유지한다.
- 테마 설정은 데이터로 관리한다. 테마를 늘릴 때 화면 로직을 복사하지 않는다.
- 저장된 테마 ID를 찾을 수 없으면 기본 테마로 표시한다.
- 기본 테마의 일반 텍스트 대비는 4.5:1 이상을 목표로 확인한다.

**완료 기준:** 세 테마가 편집 미리보기·보기 모드에 동일하게 적용되고 콘텐츠가 보존된다.

### F06. 자동 저장 — P0 제안

- 프로필·테마 변경은 마지막 입력 500ms 후 저장한다. 링크 확정·삭제·정렬은 즉시 저장한다.
- “저장 중”, “이 브라우저에 저장됨”, “저장하지 못함” 상태를 구분한다.
- 저장 성공은 localStorage 쓰기 성공 후에만 표시한다. 이미지 변환 중에는 완료로 표시하지 않는다.
- 저장 실패 시 현재 화면 데이터는 유지하고 재시도 버튼을 제공한다. 실패 시 새로고침하면 최근 변경이 사라질 수 있음을 안내한다.
- 브라우저 저장이 차단되었거나 용량을 초과해도 화면 편집은 계속 가능하다.
- 보기 모드 전환 시 대기 중인 저장을 수행한다. 탭 종료·강제 종료 직전 저장은 보장하지 않으며 상태 표시로 이를 확인할 수 있게 한다.
- 다중 탭 동시 편집·자동 병합은 이번 범위에서 제외한다. 같은 브라우저의 여러 탭에서 편집하면 마지막으로 저장한 데이터가 남을 수 있다.
- 저장 상태 안내 아래에 “이 기기의 브라우저에만 저장돼요”를 표시한다.

**완료 기준:** 정상 저장본은 재접속 후 복원되며 저장 실패를 성공으로 표시하지 않는다.

### F07. 미리보기·보기 모드 — P0

- 편집과 보기 모드는 같은 프로필 렌더링 컴포넌트를 사용한다.
- 편집 변경은 저장 완료를 기다리지 않고 미리보기에 반영한다.
- 보기 모드에서는 폼·추가·삭제·테마 선택 도구를 숨기고 편집으로 돌아가기만 제공한다.
- 사진 없음, 소개글 없음, 링크 없음 상태를 지원한다. 링크가 없으면 “아직 등록된 링크가 없어요”를 표시한다.
- 긴 제목과 소개글은 줄바꿈하며 가로 넘침이 발생하지 않도록 한다.
- 보기 모드도 현재 브라우저의 데이터를 사용한다. 별도 게시·공유 상태를 만들지 않는다.

**완료 기준:** 같은 데이터·테마가 양쪽 모드에서 일관되게 표시되고 콘텐츠를 잃지 않고 전환된다.

### F08. 예시로 초기화 — P0 제안

- “예시로 초기화” 선택 시 현재 프로필·링크·테마가 교체된다는 확인을 받는다.
- 취소하면 아무것도 바꾸지 않는다. 확인하면 예시 데이터로 교체하고 저장한다.
- 초기화는 이 앱의 저장 키만 대상으로 하며 localStorage 전체를 삭제하지 않는다.
- 저장 실패 시 화면은 예시 상태를 보여주되 초기화 결과가 저장되지 않았음을 알린다. 성공한 초기화는 되돌릴 수 없다.

**완료 기준:** 정상 초기화 후 새로고침하면 예시 데이터가 표시되고 다른 앱의 저장 데이터는 유지된다.

## 6. 향후 변경을 위한 구현 원칙

복잡한 백엔드를 미리 만들지 않고, 현재 기능에서 바뀔 부분을 분리한다. 현재 프로젝트의 Next.js App Router·TypeScript·Tailwind CSS 4 구성을 사용하며, 기능별 폴더 구조는 구현 시 결정한다.

### 디자인 시스템 초기화 — 확정·완료

- 디자인 시스템은 [shadcn/ui](https://ui.shadcn.com/ui)를 기반으로 구성한다.
- 앞으로 신규 UI를 디자인하거나 기존 UI를 수정할 때 shadcn/ui를 기본으로 사용한다. 버튼·입력·카드·대화상자 등 공통 UI는 해당 shadcn/ui 컴포넌트를 추가해 사용하고, 프로젝트 요구에 맞게 테마 변수와 스타일을 조정한다.
- shadcn/ui에 대응하는 컴포넌트가 없는 UI는 기존 디자인 시스템의 토큰과 스타일 원칙에 맞춰 구성한다. 컴포넌트 추가·적용은 해당 UI 작업 시 진행한다.
- 완료된 초기화 작업의 범위는 공식 `shadcn@latest init` CLI를 통한 설정까지다. 화면 구현과 UI 컴포넌트 추가·적용은 앞으로 해당 UI 작업에서 진행한다.
- 초기 설정은 Radix 기반 Nova 스타일(`radix-nova`), Neutral 기본 색상, Lucide 아이콘, CSS 변수 기반 테마를 사용한다. 서비스 전용 디자인 세부사항은 후속 작업에서 정한다.
- `components.json`에 컴포넌트 경로·별칭·스타일 설정을 생성하고, `src/app/globals.css`에 기본 테마 변수·Tailwind 연결을 추가했다.
- `src/lib/utils.ts`에 `cn` 유틸리티를 구성하고 `package.json`·`package-lock.json`에 초기화 의존성을 반영했다.
- 기존 프로필 화면, Pretendard 폰트, 기존 스타일은 유지한다. CLI가 자동 생성한 버튼 컴포넌트와 폰트 변경은 제거했으며, 프로필 기본 레이아웃은 자체 스타일을 유지하고 “더 알아보기”와 `/links`에는 공유 shadcn/ui LinkCard를 적용했다.
- 기본 테마 변수의 준비는 F05의 미니멀·소프트·다크 테마 기능 구현 완료를 의미하지 않는다.

**완료 기준·검증 결과:** 초기화 설정과 의존성이 준비됐으며 `npm run lint`와 `npm run build`가 모두 통과했다. 화면 변화나 UI 컴포넌트 구현은 이번 완료 기준에 포함하지 않는다.

### PRD 변경 관리 — 확정

미선정 항목에 대해 Zustand·폼·검증·DB·인증 등의 라이브러리를 현재 사용 중이거나 사용 확정으로 기록하지 않는다. 필요가 결정되면 설치·실제 적용 상태와 함께 이 문서를 갱신한다.

- TypeScript 7은 `@typescript/native` 별칭으로 설치했다. Next.js·typescript-eslint의 API 호환을 위해 `typescript`에는 `@typescript/typescript6` 6.0.2를 별칭으로 설치한다. [Microsoft 공식 병행 설치 가이드](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/#running-side-by-side-with-typescript-6.0)를 따른다.
- Next.js의 일부 린트 플러그인은 ESLint 10에서 제거된 API를 사용하므로 `eslint.config.mjs`에 공식 `@eslint/compat`의 `fixupConfigRules`를 적용했다. 플러그인의 ESLint 지원 범위에 따른 npm peer 경고는 남아 있다.
- `npm audit`는 shadcn·Next.js 린트 도구의 간접 의존성 경로에서 high 경고 9건을 보고했다. 제시된 자동 수정은 shadcn·`eslint-config-next`의 이전 주 버전 설치이므로 적용하지 않았다. 최신 버전 적용과 취약점 경고 해소는 별도로 관리한다.

**완료 기준·검증 결과:** `npm outdated --json` 결과가 빈 객체이며 `npm run lint`, `npm run build`, TypeScript 7의 `tsc --noEmit --incremental false`가 모두 통과했다. 이번 작업은 의존성과 도구 호환 설정 변경이며 화면·기능 구현은 포함하지 않는다.

### 기능별 책임

| 구분 | 책임 | 후속 변경 방법 |
| --- | --- | --- |
| 프로필 데이터 모델 | 이름·소개·사진·링크·테마 ID와 버전 정의 | 계정·페이지 ID, 게시본 등 필드 추가 |
| 편집 상태·동작 | 프로필 변경, 링크 CRUD·순서, 테마 선택 | 새로운 UI도 기존 동작을 호출 |
| 저장 어댑터 | `load`, `save`, `reset`과 오류 처리 | 브라우저 저장 구현을 API 저장 구현으로 교체 |
| 프로필 렌더러 | 전달받은 데이터·테마를 화면으로 표시 | 추후 공개 페이지에서도 재사용 |
| 테마 설정 | 테마 ID와 스타일 토큰 목록 | 테마 항목·설정값 추가 |
| 입력 검증 | 이름·소개·URL·사진 제한 | 정책 값 변경, 서버 검증과 연결 |
| 사진 처리 | 선택 파일 변환·용량 검증 | 나중에 업로드 서비스 구현으로 교체 |
| 예시 데이터 | 최초 접속·초기화 기본값 | 샘플 내용만 교체 |

- 화면 컴포넌트가 localStorage를 직접 읽고 쓰지 않는다. 저장 어댑터를 통해 처리한다.
- 저장 계약은 비동기 호출 형태로 정의해 향후 서버 요청을 연결할 수 있게 한다. 네트워크 기능 자체는 구현하지 않는다.
- 이름 길이·사진 용량 등 제한은 한곳의 설정값으로 관리한다.
- 링크 ID는 내용·순서와 독립적이다. 수정과 이동 시 새 ID를 만들지 않는다.
- 데이터는 직렬화 가능한 형태로 관리하며 `schemaVersion`을 포함한다. 저장 키는 `mylink.profile`처럼 앱 전용 이름을 사용한다.
- 저장 데이터는 읽을 때 구조와 값의 유효성을 검증한다. 스키마 변경 시 이전 버전 마이그레이션 함수를 추가할 수 있게 한다.
- 비밀키·인증 토큰·개인 계정 정보는 저장 데이터에 포함하지 않는다.

### 저장 데이터 예시

```json
{
  "schemaVersion": 1,
  "profile": {
    "name": "김마이",
    "bio": "제가 만든 것들을 소개합니다.",
    "avatar": null
  },
  "links": [
    {
      "id": "link-unique-id",
      "title": "포트폴리오",
      "description": "직접 만든 프로젝트와 작업물을 소개해요.",
      "url": "https://example.com/portfolio",
      "icon": "FolderOpen",
      "category": "portfolio",
      "actionText": "작업 보기",
      "isExternal": true,
      "badge": "추천",
      "displayOrder": 1
    }
  ],
  "themeId": "minimal"
}
```

`avatar`는 이번 버전에서 `null` 또는 변환된 이미지 data URL이다. 향후 서버 저장 시 이미지 파일 참조로 변경할 수 있다. 링크 순서는 `displayOrder`로 표현하고 저장 배열도 같은 오름차순으로 유지한다.

## 10. 후속 확장 항목

| 확장 | 추가 작업 |
| --- | --- |
| 로그인·서버 저장 | 인증, 소유권, 계정·페이지 모델, 저장 API·서버 검증 |
| 개인 공개 주소 | 아이디 정책, 서버 조회, 라우팅, 중복 처리 |
| 게시·공개 중지 | 초안·게시본 분리, 게시 상태·캐시 정책 |
| 주소·QR 공유 | 실제 공개 URL 생성 후 복사·QR 기능 연결 |
| 더 풍부한 꾸미기 | 테마 항목 추가, 커스텀 색상·사진 자르기 |
| 링크 편집 편의 | 드래그 정렬, 숨김, 삭제 실행 취소 |

이번 설계는 화면과 저장 처리의 결합을 줄이기 위한 것이다. 로그인·공개 게시를 추가할 때는 데이터 모델과 제품 정책도 확장해야 하며, 저장 어댑터 교체만으로 모든 후속 기능이 완성되지는 않는다.
