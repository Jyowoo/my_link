# 마이링크 PRD · 테스트 페이지 기능 정의서

버전: 1.18 | 수정일: 2026-11-07 | 용도: 팀 개발 포트폴리오용 프런트엔드 시제품

이 버전은 기존 서비스 MVP 명세를 대체한다. 현재 목표는 프로필·링크를 직접 수정하고 테마를 바꾸는 경험을 테스트하는 것이다. **확정**은 사용자가 지정한 방향이고, **제안**은 구현을 위한 기본 정책이다. Google 소셜 로그인과 Cloud Firestore 사용자별 링크 저장을 구현했다. 별도 회원가입 폼은 제공하지 않는다.

**현재 구현과 목표 구분:** 현재 프로젝트는 사용자 프로필 페이지(`/`)와 Firestore 기반 개인 링크 관리 페이지(`/links`)다. 아래 제품 흐름·화면·F01~F08·인수 테스트는 구현 완료와 후속 목표를 구분해 기록하며, 완료 상태는 2장의 현황과 6장의 기술 목록을 기준으로 판단한다. 기술 현황은 `package.json`, `package-lock.json`, 설정 파일과 `src/`의 실제 사용 코드를 대조했다.

## 1. 제품 목표

마이링크는 일반 개인이 사진, 이름, 소개글과 SNS·작업물 링크를 한 화면에 정리하는 자기소개 페이지다. 첫 버전에서는 편집과 미리보기의 사용성을 검증한다. 기본 기능을 무료로 충분히 제공한다는 방향을 유지한다.

목표 버전에서는 사용자가 페이지에 접속하면 바로 예시 프로필을 편집할 수 있어야 한다. 프로필 이름·소개는 Firestore에 저장하며, 테마 편집·저장은 후속 제안이다. 링크 추가·조회·수정·삭제는 로그인한 사용자의 Firestore 컬렉션을 사용한다. 주소 아이디 기반 공개 페이지는 구현했으며 별도 게시·공개 중지 정책은 후속 작업이다.

### 링크 목록 페이지 — 구현 완료

- 경로는 `/links`다. 로그인 후 프로필 “더 알아보기” 제목 오른쪽의 굵은 “링크 관리” 버튼으로 이동한다. 프로필 최상단에서는 해당 버튼을 제거했다. 목록 페이지에는 프로필로 돌아가는 링크를 제공한다.
- Firestore의 `users/{uid}/links`를 `displayOrder` 오름차순으로 구독해 표시한다. 제목·설명·분류·동작 문구·아이콘·선택적 배지를 보여주며 ID를 목록 키로 사용한다.
- shadcn/ui Card·Badge·Button과 Tailwind CSS·Lucide 아이콘을 사용하며 모바일·PC에 맞춰 여백과 줄바꿈을 구성한다.
- 카드 전체·제목·설명 클릭으로 이동하지 않으며 “링크 열기” 등 동작 버튼만 이동한다. 외부 링크는 새 탭으로 열고 `noopener noreferrer`를 적용한다. 보조 기술에 새 탭 열기를 안내하고 키보드 포커스를 표시한다.
- 저장 데이터의 `Instagram` 아이콘 이름은 현재 Lucide 버전의 지원 아이콘인 `MessageCircle`로 매핑한다. 알 수 없는 아이콘은 `Link2`, 미등록 분류는 원래 식별자로 표시한다.
- 배지가 `null`이면 생략하며 링크가 없으면 빈 목록 안내를 표시한다. 로딩·조회 실패 안내를 제공하고, 조회 중이거나 실패한 상태에서는 추가 버튼을 비활성화한다.
- 관리 화면에는 수정·삭제 버튼을 항상 표시한다. 프로필 카드에는 표시하지 않는다. “저장한 링크는 새로고침해도 유지돼요” 안내는 제거했다. 정렬·테마 선택·범용 보기 모드 전환은 구현 예정이다.

기존 Jyowoo 고정 소개·기술 스택·GitHub 버튼은 로그인 사용자 정보와 비로그인 안내 화면으로 대체했다.

## 3. 현재 사용자 흐름

1. 로그인 상태 확인 중에는 확인 안내를 표시한다.
2. 비로그인 시 헤더에만 Google 로그인 버튼을 표시하고 본문에는 로그인 후 사용할 수 있다는 설명을 제공한다.
3. 로그인하면 사용자 정보와 본인 링크를 읽고 “링크 관리” 및 로그아웃 버튼을 표시한다.
4. 관리 페이지에서 링크를 추가하거나 카드의 인라인 수정·삭제 확인창을 사용한다.
5. 변경은 Firestore에 저장하며 프로필과 관리 목록에 반영한다.
6. 로그아웃·계정 변경 시 기존 구독·목록·폼을 분리하고 이전 계정에서 캡처한 변경 요청을 거절한다.

프로필 수정은 구현했으며 테마 선택·편집과 연동되는 실시간 미리보기·예시 초기화는 후속 목표다. 현재는 읽기 전용 /preview 페이지를 제공한다. /[username] 공개 주소를 제공하며 별도 게시본은 없다.

PC에서는 편집 패널과 미리보기를 함께 보여준다. 모바일에서는 편집·미리보기 전환을 제공한다. 보기 모드는 같은 앱 안의 화면 상태이며 별도 공유 페이지가 아니다.

## 5. 기능 명세

아래 숫자와 동작 세부사항은 **제안**이다. 첫 버전 필수 기능을 P0으로 정의한다. F01의 Firestore 링크 조회·재접속 조회와 F03의 링크 CRUD·영속 저장은 구현했다. 프로필·테마 초기화·복원, 링크 정렬과 나머지 기능은 미구현이며 전체 F01·F03·F06 완료로 보지 않는다.

### F01. 초기 데이터·복원 — P0 · 링크 조회 구현, 나머지 예정

**현재 링크 동작:** Firestore를 조회하며 컬렉션이 비어 있으면 빈 목록을 표시한다. 예시 데이터로 자동 대체하지 않는다. 다음 샘플 초기화·저장 데이터 검증·복원 정책은 후속 목표이며 링크 조회 오류 처리와 구분한다.

- 저장 데이터가 없으면 샘플 이름, 소개글, 기본 아바타, 예시 링크 3개와 미니멀 테마를 표시한다.
- 예시 데이터와 테마 설정은 한곳에서 관리해 쉽게 교체할 수 있게 한다.
- 링크 목록용 더미 데이터 3개를 `src/data/demo-links.json`에 작성했다. 포트폴리오·블로그·SNS 예시이며 `id`, `title`, `description`, `url`, `icon`, `category`, `actionText`, `isExternal`, `badge`, `displayOrder`의 10개 필드를 사용한다.
- 더미 URL은 `https://example.com`의 예시 경로로 작성하며 실제 개인 계정이나 콘텐츠 주소가 아니다. 현재 런타임에는 연결하지 않는다. 최초 접속 편집 데이터·예시 초기화 시 적용은 후속 정책 결정 후 진행한다.
- 저장 데이터가 있으면 검증 후 복원한다. 유효하지 않은 필드에는 기본값을 적용한다.
- JSON 파싱 실패 등으로 복원이 불가능하면 예시 화면과 “저장된 데이터를 읽지 못했어요.” 안내를 표시한다. 실패한 원본을 자동으로 덮어쓰지 않는다.
- 복원 오류 시 저장을 일시 중단하고, 사용자가 확인 후 초기화하면 정상 저장을 재개한다.

**완료 기준:** 첫 접속과 재접속이 구분되며 잘못된 저장 데이터 때문에 빈 화면이나 앱 중단이 발생하지 않는다.

### F02. 프로필 수정·표시 이름 중복 방지 — 구현 완료

- 프로필 드롭다운의 “프로필 수정”에서 /settings/profile로 이동한다. 로그인한 사용자만 편집하며 이메일은 읽기 전용이다.
- 표시 이름은 NFKC 정규화·앞뒤 공백 제거 후 2~30자의 한글·영문·숫자·._+-를 허용한다. 영문 대소문자는 중복 판정 시 구분하지 않는다.
- 중복 확인은 displayNames/{정규화된 소문자 이름}을 서버에서 조회한다. 입력 변경 시 확인 결과를 무효화하고 저장 시 트랜잭션으로 다시 검사한다. 동시 등록은 한 사용자만 성공한다.
- 이름 변경은 새 이름 예약·users/{uid} 수정·이전 이름 해제를 원자적으로 수행한다. 이미 사용하는 이름이면 입력을 유지하고 오류를 표시한다.
- 소개는 최대 200자이며 일반 텍스트로 저장·표시한다. 저장·중복 확인 실패는 오류를 표시하고 재시도할 수 있다. 저장 성공은 Sonner로 안내한다.
- 프로필 사진 주소 수정·업로드 UI는 제외했다. 기존 Google 사진은 유지하며 이름·소개 저장 시 사진을 변경하지 않는다.
- 신규 이름은 이메일 접두사에서 생성한다. 재로그인·인증 복원은 사용자 지정 이름·소개를 유지하며 기존 계정의 이름 예약도 준비한다. 이름 충돌 시 UID 일부를 붙인다.
- links·preview·settings·api·_next·favicon.ico·robots.txt·sitemap.xml 및 점 경로는 서비스 예약 이름으로 사용할 수 없다.
- 표시 이름을 바꿔도 주소는 유지된다. 프로필 편집에서 3~30자의 주소 아이디를 별도로 변경·중복 확인할 수 있다. 저장 트랜잭션은 주소 예약·프로필 갱신·이전 주소 해제를 원자적으로 처리한다. 기존 계정은 인증 복원 시 주소를 생성한다. 이전 표시 이름 URL은 새 주소로 교체되며 자동 리디렉션은 없다.

**검증:** verify-profile.mjs의 정규화·유효성·이름 충돌·사용자 지정 이름 유지·동시 예약·이전 이름 해제·계정 변경 거절 모의 검사 통과. 실제 배포 규칙·에뮬레이터 경합 검증은 미수행이다.
### F03. 링크 추가·수정·삭제 — P0

| 항목 | 규칙 |
| --- | --- |
| 제목 | 앞뒤 공백 제거 후 1~50자, 필수 |
| URL | 앞뒤 공백 제거 후 최대 2,048자, 유효한 `https://`·`http://` 절대 주소, 필수 |
| ID | 생성 시 고유 식별자 부여, 제목·URL 수정 시 유지 |
| 순서 | `displayOrder` 오름차순 기준, 새 링크는 맨 끝에 추가; 정렬 변경 시 배열과 순서 값을 함께 갱신 |

#### 링크 데이터 구조 — 확정

| 필드 | 타입 | 의미·예시 |
| --- | --- | --- |
| `id` | string | Firestore 자동 문서 ID를 조회 시 주입; 문서 본문에 중복 저장하지 않음 |
| `title` | string | 링크 제목 |
| `description` | string | 링크 설명, 설명이 없으면 빈 문자열 |
| `url` | string | 이동할 HTTP·HTTPS 절대 주소 |
| `icon` | string | Lucide 아이콘 이름, 현재 예시는 `FolderOpen`·`BookOpen`·`Instagram` |
| `category` | string | 분류 식별자, 추가 폼은 `portfolio`·`blog`·`social`·`other` |
| `actionText` | string | 이동 동작 문구, 예: “작업 보기” |
| `isExternal` | boolean | 외부 링크 여부, 새 링크는 `true`로 생성 |
| `badge` | string 또는 null | 강조 문구, 예: “추천”·“NEW”; 없으면 `null` |
| `displayOrder` | number | 추가 시 현재 조회 목록의 최댓값 + 1; 동시 추가 시 중복 방지는 미구현 |
| `createdAt` | Firestore Timestamp | 생성 시 `serverTimestamp()`로 저장하는 서버 시각; 화면용 `ProfileLink` 타입에는 미포함 |

아이콘은 JSON에 컴포넌트 대신 이름으로 저장하고, 화면 구현 시 허용된 Lucide 아이콘 매핑으로 렌더링한다. 분류·설명·동작 문구·배지는 추가 폼에서 입력하며 기존 링크 수정도 같은 공통 폼을 사용한다. `isExternal`은 외부 여부를 나타내며 F03의 새 탭 열기 정책은 유지한다.

- “링크 추가”를 누르면 제목·URL 폼을 제공한다. 확인 시 검증을 통과한 링크만 목록에 추가한다.
- 수정은 관리 카드 안의 인라인 폼에서 확인한 뒤 목록에 반영한다. 미완성 폼은 미리보기와 저장 데이터에 포함하지 않는다.
- 취소하면 기존 링크를 유지한다. 미완성 입력이 있는 상태에서 보기 모드나 초기화로 이동할 때는 입력을 버릴지 확인한다.
- 삭제 시 확인 대화상자를 제공한다. 취소하면 유지하고 확인하면 삭제한다.
- 링크 개수에 제품상 상한을 두지 않는다. Firestore 저장 실패는 추가 폼에서 안내한다.
- 같은 URL의 반복 등록을 허용한다. 제목 없는 링크는 저장할 수 없다.
- URL 형식만 검증한다. 대상 사이트의 접속 가능 여부는 검사하지 않는다.
- `javascript:`, `data:` 등 다른 스킴은 거절한다. 이메일·전화 전용 링크는 후속 범위다.
- 미리보기·보기 모드에서 링크를 누르면 새 탭으로 열고 `noopener noreferrer`를 적용한다.

**완료 기준:** 유효한 링크의 추가·수정·삭제가 미리보기와 저장에 반영되며 잘못된 입력은 해당 필드에 오류를 표시한다.

#### 링크 추가 다이얼로그 — Firestore 저장 구현 완료

- `/links`의 “링크 추가” 버튼에서 shadcn/ui Dialog를 연다. 제목·URL은 필수이며 설명·분류·동작 문구·배지는 선택 또는 기본값을 제공한다.
- 제목은 앞뒤 공백 제거 후 사용자에게 보이는 문자 기준 1~50자, URL은 최대 2,048자의 HTTP·HTTPS 절대 주소로 검증한다. 오류는 필드 아래에 표시하고 첫 오류 입력으로 포커스를 옮긴다.
- URL은 프로토콜 선택과 주소 입력을 분리하며 HTTPS가 기본값이다. 전체 HTTP·HTTPS URL 붙여넣기 시 프로토콜과 주소를 자동 분리한다. 다른 스킴은 거절한다.
- 분류는 작업물·기록·일상·기타이며 아이콘을 자동 지정한다. 빈 동작 문구는 “링크 열기”, 빈 배지는 `null`, 외부 여부는 `true`로 저장한다. 중복 URL은 허용한다.
- `addDoc`로 `users/{uid}/links/{자동 ID}`에 생성한다. 기존 최대 `displayOrder` + 1과 `createdAt: serverTimestamp()`를 함께 저장한다. 동시 작성자의 순서 값 충돌 방지는 아직 없다.
- 서버 저장 확인 후 다이얼로그를 닫는다. 저장 중에는 “저장 중…” 표시, 입력·취소·중복 제출·닫기 방지를 적용한다. 실패하면 입력값을 유지하고 오류를 표시하며 다시 제출할 수 있다.
- 저장하지 않을 때 취소·닫기·Escape는 데이터를 변경하지 않으며 재개방 시 폼을 초기화한다. Radix Dialog의 키보드·포커스 관리를 사용한다.
- 오프라인 쓰기는 연결 복구 전까지 대기할 수 있다. 별도 타임아웃·오프라인 취소·오프라인 상태 안내는 미구현이다.
- 페이지 메타데이터는 서버 컴포넌트, 목록·저장 상태는 `LinksProvider`·`LinksList`, 입력은 `AddLinkDialog`, 검증·화면 타입은 `src/lib/links.ts`에서 관리한다.

#### 링크 인라인 수정·삭제 — 구현 완료

- 추가·수정은 `LinkForm`과 `validateLink`를 공유한다. 제목 1~50자, HTTP·HTTPS URL 최대 2,048자, 필수 입력·다른 스킴 거절·오류 포커스 정책을 동일하게 적용한다.
- 수정은 현재 제목·URL·설명·분류·동작 문구·배지를 채운 인라인 폼이다. 취소 시 원본을 유지한다. 저장은 `updateDoc(users/{uid}/links/{id})`를 사용하며 ID·displayOrder·createdAt을 보존하고 updatedAt 서버 시각을 기록한다.
- 삭제는 링크 이름과 “정말 삭제하시겠습니까?” 제목, 빨간색 “이 작업은 되돌릴 수 없습니다” 경고, 취소·삭제하기 버튼을 표시한다. 취소 시 요청하지 않고 확인 시 `deleteDoc`를 사용한다.
- 저장·삭제 중 중복 제출을 막고, 실패하면 폼·카드와 오류를 유지해 재시도할 수 있다. 서버 확인 전 로컬 변경으로 카드가 사라지지 않도록 처리한다.
- `LinkCard`는 필수 `mode: view | manage`로 구분한다. 프로필은 view, 관리 페이지는 manage이며 관리 화면에서만 수정·삭제 UI를 렌더링한다.

#### 프로필 링크 목록 연결 — Firestore 구독 구현 완료

- `AuthProvider` 안의 `LinksProvider`가 로그인 UID별 컬렉션을 구독한다. UID를 key로 데이터 영역을 재생성하고 이전 구독을 해제하며 늦게 도착한 콜백은 무시한다. 대기 중 쓰기와 삭제는 서버 확인 전 기존 카드를 유지한다.
- `/links`와 프로필 “더 알아보기”가 같은 목록과 `LinkCard`를 사용한다. 새로고침·재접속 시 Firestore를 다시 조회하며 기본 더미로 되돌리지 않는다.
- 두 화면 모두 로딩·조회 오류·빈 목록 상태를 구분한다. 조회 실패 시 새로고침을 안내하며 `/links`의 추가 버튼은 조회 중·조회 실패 시 비활성화한다.
- `orderBy("displayOrder")`로 조회하므로 외부에서 넣는 문서에도 해당 필드가 필요하다. 조회 결과의 런타임 스키마 검증·기본값 보정은 아직 없다.

#### Firestore 설정·검증 현황

- `src/lib/firebase.ts`에서 기존 Firebase 앱을 재사용하고 `getFirestore`를 초기화한다. `.env.example`의 `NEXT_PUBLIC_FIREBASE_*` 설정을 `.env.local` 및 배포 환경에 입력한다. 브라우저용 설정은 빌드 시 포함되며 `.env.local`은 Git에서 제외한다.
- 설정한 프로젝트에 Firestore 데이터베이스가 필요하며 배포된 보안 규칙은 `request.auth.uid == uid`인 소유자에게만 사용자 문서·링크 CRUD를 허용해야 한다. 저장소의 `firestore.rules`를 준비했으며 실제 콘솔 배포는 아직 수행하지 않았다.
- 개인화 전 공용 경로는 자동 이관하지 않는다. 현재는 Firebase Auth UID와 소유자 규칙으로 계정을 분리하며 익명 로그인은 제공하지 않는다.
- 2026-11-03 커밋 검증에서 린트·타입·프로덕션 빌드와 인증·변경 모의 검사를 확인한다. 이전 단계에서 브라우저로 관리 버튼·인라인 폼·삭제창 열기를 확인했으나 실제 OAuth와 개인 계정 CRUD·배포 규칙의 통합 검증은 미완료다.
- 이전 로컬 상태 구현의 Chrome 검증은 입력 검증·키보드·모바일 UI에 대한 과거 결과이며 현재 Firestore 저장 성공의 증거로 간주하지 않는다.
- `scripts/verify-link-dialog.mjs`는 현재 목록 개수를 기준으로 추가·프로필 공유·새로고침 후 유지·모바일 추가를 검사하도록 수정했다. Windows Node.js·Chrome과 개발 서버, 쓰기 가능한 테스트 Firebase 프로젝트가 필요하다. 현재 인증 흐름을 자동 수행하지 않으므로 로그인된 테스트 프로필이 필요하다. 테스트 링크 2개를 영구 생성하며 자동 삭제하지 않으므로 동시 쓰기가 없는 테스트 데이터에서 실행한다. 수정된 시나리오의 실행은 미완료다.

#### 링크 클릭 집계 — 구현 완료

- 링크 열기 클릭을 Firestore의 clickCount에 원자적으로 1씩 더한다. 신규 링크는 0으로 저장하고 기존 링크에 필드가 없으면 0으로 표시한다. 로그인한 소유자는 제외하며, 같은 방문자의 여러 클릭은 각각 집계한다.
- 내 프로필과 링크 관리 카드에 눈 아이콘과 숫자를 표시한다. 공개 페이지와 미리보기는 집계는 유지하되 숫자를 숨긴다.
- 방문자는 clickCount만 정확히 1 증가시킬 수 있고, 소유자는 링크 내용을 수정할 수 있지만 카운터는 변경할 수 없다. 콘솔에 전체 공개 테스트 규칙을 남기면 제한이 적용되지 않으므로 전체 규칙 파일로 교체한다.
- 타입 검사와 기존 링크·공개 프로필 모의 검사를 수행했다. 실제 Firestore의 쓰기 권한 및 저장 검증은 별도다.

### F04. 링크 순서 변경 — P0 제안

- 각 링크에 위로·아래로 이동 버튼을 제공한다. 키보드·마우스·터치로 조작할 수 있다.
- 첫 링크의 위로 이동, 마지막 링크의 아래로 이동은 비활성화한다.
- 변경 즉시 미리보기와 저장 데이터에 반영한다.
- 드래그 정렬은 추후 같은 순서 변경 동작을 호출하도록 추가한다.

**완료 기준:** 변경한 순서가 보기 모드와 재접속 후에도 유지된다.

### F05. 테마 변경 — P0

- 미니멀, 소프트, 다크 테마 3개를 제공한다.
- 테마는 배경색, 이름·소개 글자색, 버튼색·글자색·모서리·간격의 사전 정의된 조합이다.
- 테마 선택 시 프로필·링크 데이터는 유지하고 시각 스타일만 바뀐다.
- 선택한 테마를 구분해 표시하며 새로고침 후에도 유지한다.
- 테마 설정은 데이터로 관리한다. 테마를 늘릴 때 화면 로직을 복사하지 않는다.
- 저장된 테마 ID를 찾을 수 없으면 기본 테마로 표시한다.
- 기본 테마의 일반 텍스트 대비는 4.5:1 이상을 목표로 확인한다.

**완료 기준:** 세 테마가 편집 미리보기·보기 모드에 동일하게 적용되고 콘텐츠가 보존된다.

### F06. 저장 — 링크 CRUD·프로필 확정 저장 구현, 테마 자동 저장은 제안

링크 추가는 F03의 Firestore 저장 계약을 따른다. 아래 localStorage·500ms 지연 저장·모드 전환 정책은 후속 테마 편집을 위한 제안이며 현재 링크 저장에는 적용하지 않는다.

- 프로필 이름·소개는 저장 버튼으로 Firestore에 확정 저장한다. 링크 CRUD는 즉시 저장하며 테마 자동 저장·링크 정렬은 후속 구현 대상이다.
- “저장 중”, “이 브라우저에 저장됨”, “저장하지 못함” 상태를 구분한다.
- 저장 성공은 localStorage 쓰기 성공 후에만 표시한다. 이미지 변환 중에는 완료로 표시하지 않는다.
- 저장 실패 시 현재 화면 데이터는 유지하고 재시도 버튼을 제공한다. 실패 시 새로고침하면 최근 변경이 사라질 수 있음을 안내한다.
- 브라우저 저장이 차단되었거나 용량을 초과해도 화면 편집은 계속 가능하다.
- 보기 모드 전환 시 대기 중인 저장을 수행한다. 탭 종료·강제 종료 직전 저장은 보장하지 않으며 상태 표시로 이를 확인할 수 있게 한다.
- 프로필·테마의 다중 탭 동시 편집·자동 병합은 제안 범위에서 제외한다. 링크는 Firestore 구독으로 변경을 수신하지만 순서 충돌 해결은 미구현이다. 같은 브라우저의 여러 탭에서 편집하면 마지막으로 저장한 데이터가 남을 수 있다.
- 저장 상태 안내 아래에 “이 기기의 브라우저에만 저장돼요”를 표시한다.

**완료 기준:** 정상 저장본은 재접속 후 복원되며 저장 실패를 성공으로 표시하지 않는다.

### F07. 미리보기·보기 모드 — 읽기 전용 페이지 구현, 편집 연동은 P0 목표

현재 /preview는 본인 사용자 정보와 읽기 전용 링크 목록을 표시한다. 수정·삭제·링크 관리 버튼을 숨기고 프로필로 돌아가는 링크를 제공한다. 새 탭에서 열며 noindex·nofollow를 설정한다. 비로그인 시 로그인 안내를 표시한다. 아래 실시간 편집 연동·모드 전환 정책은 후속 목표다.

- 편집과 보기 모드는 같은 프로필 렌더링 컴포넌트를 사용한다.
- 편집 변경은 저장 완료를 기다리지 않고 미리보기에 반영한다.
- 보기 모드에서는 폼·추가·삭제·테마 선택 도구를 숨기고 편집으로 돌아가기만 제공한다.
- 사진 없음, 소개글 없음, 링크 없음 상태를 지원한다. 링크가 없으면 “아직 등록된 링크가 없어요”를 표시한다.
- 긴 제목과 소개글은 줄바꿈하며 가로 넘침이 발생하지 않도록 한다.
- 보기 모드의 프로필·테마는 브라우저 편집 데이터를 사용하고 링크는 본인의 Firestore 목록을 사용하도록 한다. 별도 게시 상태를 만들지 않는다.

**완료 기준:** 같은 데이터·테마가 양쪽 모드에서 일관되게 표시되고 콘텐츠를 잃지 않고 전환된다.

### F08. 예시로 초기화 — P0 제안 · 미구현

아래는 브라우저 프로필·테마를 위한 초기 제안이다. Firestore 개인 링크 초기화는 별도 권한·확인·대상 정책을 정하기 전에는 구현하지 않는다.

- “예시로 초기화” 선택 시 브라우저의 프로필·테마가 교체된다는 확인을 받는다. Firestore 링크는 별도 정책 결정 대상이다.
- 취소하면 아무것도 바꾸지 않는다. 확인하면 예시 데이터로 교체하고 저장한다.
- 브라우저 초기화는 이 앱의 프로필·테마 저장 키만 대상으로 하며 localStorage 전체나 Firestore 컬렉션을 삭제하지 않는다.
- 저장 실패 시 화면은 예시 상태를 보여주되 초기화 결과가 저장되지 않았음을 알린다. 성공한 초기화는 되돌릴 수 없다.

**완료 기준:** 정상 초기화 후 새로고침하면 예시 데이터가 표시되고 다른 앱의 저장 데이터는 유지된다.

### Google 인증·로그인 UI — 구현 완료

- 헤더에 Google 로그인 버튼 하나만 둔다. 중앙 “Google로 시작하기” 버튼은 제거하고 로그인 후 이용 설명만 표시한다. 로그인 후에는 사용자 이름을 누르면 열리는 프로필 드롭다운을 제공하며 로그아웃은 메뉴 안에 배치한다.
- Firebase Auth `signInWithPopup`과 Google 공급자를 사용하며 계정 선택을 요청한다. 로그인 상태 복원은 `onAuthStateChanged`로 처리한다.
- SDK가 팝업 종료를 늦게 통지해도 “로그인 중…” 문구나 버튼 잠금을 유지하지 않는다. 사용자는 즉시 재시도할 수 있고 새 요청이 이전 요청을 대체한다. 시도 번호로 이전 오류가 최신 상태를 덮어쓰지 않게 한다.
- 프로필 병합 저장은 인증 완료와 분리한다. Firestore 저장 지연이 로그인·로그아웃을 막지 않으며 이전 계정의 저장 오류가 로그아웃 후 표시되지 않도록 한다.
- Firebase 콘솔에서 Google 공급자 활성화와 localhost·서비스 도메인 허용이 필요하다. 팝업 차단·허용 도메인·공급자 비활성화 오류를 안내한다. 실제 Google 로그인·콘솔 설정은 미검증이다.
- `scripts/verify-auth.mjs`는 로그인·로그아웃, 팝업 취소·지연·재시도, 이전 오류 무시, 프로필 저장 비차단, 헤더 전용 로그인 UI를 모의 검사한다. `scripts/verify-link-mutations.mjs`는 공유 검증·CRUD 경로·비로그인 차단·계정 변경 시 이전 동작 거절·서버 확인 전 카드 유지를 검사한다.

### 프로필 드롭다운·링크 복사·Sonner — 구현 완료

- Radix 기반 DropdownMenu를 사용해 키보드 탐색·Escape 닫기·포커스 관리를 제공한다. 메뉴 상단에 이름·이메일을 표시하고 프로필 수정·내 페이지로 이동·링크 복사·내 페이지 미리보기·로그아웃을 제공한다.
- 링크 복사는 현재 origin과 /{username}을 합친 공개 프로필 주소를 복사한다. 주소 아이디는 소문자 영문·숫자·밑줄·하이픈을 사용한다. 로그인하지 않은 방문자도 주소의 사용자 프로필·링크를 볼 수 있다.
- 내 페이지 미리보기는 /preview를 새 탭으로 열며 noopener noreferrer를 적용한다.
- Sonner 2.0.8을 설치하고 루트 레이아웃에 Toaster 하나를 배치한다. 복사 성공·실패는 toast.success·toast.error로 알리고 같은 알림 ID로 중복을 대체한다. 다른 입력 검증·인증 오류는 기존 표시 방식을 유지한다.
- 토스트는 중앙 상단에 표시하며 기본 2초 후 자동 닫힌다. 시스템 테마·성공/실패 색상·닫기 버튼을 적용하고 제목 16px 볼드, 설명 14px 중간 굵기, 높은 대비·여백·그림자를 사용한다.
- verify-auth.mjs에서 복사 URL·성공/실패 토스트·미리보기 새 탭 속성·드롭다운 로그아웃 호출을 모의 검사한다. 실제 브라우저 메뉴 키보드·클립보드 권한·화면 배치는 별도 시각 검증 대상이다.

### 표시 이름 기반 공개 페이지 — 구현 완료

- /[username] 동적 서버 페이지에서 이름을 조회한다. 경로 값을 decodeURIComponent로 한 번 디코딩하고 주소 검증·정규화 후 usernames/{username}을 읽는다. 해당 문서의 uid로 users/{uid}/links를 displayOrder 오름차순 조회한다.
- 이름이 없거나 잘못된 이름·예약 이름이면 notFound()로 전용 404를 표시한다. 데이터베이스 연결·권한 오류는 존재하지 않는 사용자로 위장하지 않고 서버 오류로 전파한다.
- 공개 주소 문서에는 uid·username·displayName·bio·photoURL만 저장한다. 이메일은 users/{uid}에만 보관하고 공개 조회 코드에서는 사용자 비공개 문서를 읽지 않는다.
- 공개 화면은 이름·소개·사진·링크만 표시한다. 수정·삭제 도구는 숨기며 헤더와 프로필 메뉴에 로그인한 본인의 개인 페이지 이동을 제공한다.
- 프로필 트랜잭션은 이름 예약 문서의 공개 필드와 비공개 사용자 문서를 함께 갱신한다. 기존 UID만 있는 예약 문서는 재로그인·인증 복원 또는 프로필 저장 시 갱신한다. 일괄 마이그레이션은 수행하지 않았다.
- firestore.rules는 공개 주소 단건 조회와 links·profile 하위 문서의 누구나 읽기를 허용한다. 쓰기는 로그인한 경로 소유자만 가능하고 공개 프로필 필드는 원본과 일치해야 한다. 현재 편집 원본 users/{uid}는 비공개다. 전체 이름 목록 조회·타 계정 수정은 허용하지 않으며 사용자 문서는 소유자만 읽는다. 새 규칙은 실제 Firebase 프로젝트에 적용해야 한다.
- 2026-11-03 정철훈의 실제 공개 문서 존재를 확인했다. 이 Next.js 버전이 인코딩된 경로를 전달하는 문제를 수정하고 개발 서버의 네트워크 제한을 해소한 뒤 해당 한글 주소의 HTTP 200 및 제목 “정철훈” 렌더링을 확인했다.
- verify-public-profile.mjs에서 존재하지 않는 이름·예약 이름·한글 인코딩/일반 문자열·잘못된 인코딩·대소문자·사용자 링크 경로·이메일 제외·위험 URL 필터링·DB 오류 전파를 모의 검사한다.

## 6. 향후 변경을 위한 구현 원칙

복잡한 백엔드를 미리 만들지 않고, 현재 기능에서 바뀔 부분을 분리한다. 현재 프로젝트의 Next.js App Router·TypeScript·Tailwind CSS 4 구성을 사용하며, 기능별 폴더 구조는 구현 시 결정한다.

### 디자인 시스템 초기화 — 확정·완료

- 디자인 시스템은 [shadcn/ui](https://ui.shadcn.com/ui)를 기반으로 구성한다.
- 앞으로 신규 UI를 디자인하거나 기존 UI를 수정할 때 shadcn/ui를 기본으로 사용한다. 버튼·입력·카드·대화상자 등 공통 UI는 해당 shadcn/ui 컴포넌트를 추가해 사용하고, 프로젝트 요구에 맞게 테마 변수와 스타일을 조정한다.
- shadcn/ui에 대응하는 컴포넌트가 없는 UI는 기존 디자인 시스템의 토큰과 스타일 원칙에 맞춰 구성한다. 컴포넌트 추가·적용은 해당 UI 작업 시 진행한다.
- 완료된 초기화 작업의 범위는 공식 `shadcn@latest init` CLI를 통한 설정까지다. 화면 구현과 UI 컴포넌트 추가·적용은 앞으로 해당 UI 작업에서 진행한다.
- 초기 설정은 Radix 기반 Nova 스타일(`radix-nova`), Neutral 기본 색상, Lucide 아이콘, CSS 변수 기반 테마를 사용한다. 서비스 전용 디자인 세부사항은 후속 작업에서 정한다.
- `components.json`에 컴포넌트 경로·별칭·스타일 설정을 생성하고, `src/app/globals.css`에 기본 테마 변수·Tailwind 연결을 추가했다.
- `src/lib/utils.ts`에 `cn` 유틸리티를 구성하고 `package.json`·`package-lock.json`에 초기화 의존성을 반영했다.
- 기존 프로필 화면, Pretendard 폰트, 기존 스타일은 유지한다. CLI가 자동 생성한 버튼 컴포넌트와 폰트 변경은 제거했으며, 프로필 기본 레이아웃은 자체 스타일을 유지하고 “더 알아보기”와 `/links`에는 공유 shadcn/ui LinkCard를 적용했다.
- 기본 테마 변수의 준비는 F05의 미니멀·소프트·다크 테마 기능 구현 완료를 의미하지 않는다.

**완료 기준·검증 결과:** 초기화 설정과 의존성이 준비됐으며 `npm run lint`와 `npm run build`가 모두 통과했다. 화면 변화나 UI 컴포넌트 구현은 이번 완료 기준에 포함하지 않는다.

### PRD 변경 관리 — 확정

- 프로젝트 수정 중에는 매번 문서를 갱신할 필요 없이, Git에 변경 사항을 저장하는 커밋 시점에 이 문서(`docs/mylink-prd.md`)를 업데이트한다.
- 모든 커밋 전에 실제 변경 사항과 PRD를 대조하고, 해당 변경 내용을 반영한 문서를 같은 커밋에 포함한다.
- 변경된 요구사항·범위·완료 상태를 반영하고, 계획과 실제 완료 내용을 구분한다.

### 기술별 현재 구현·후속 상태

| 항목 | 결정·상태 | 적용 시점 |
| --- | --- | --- |
| shadcn/ui 공통 컴포넌트 | Card·Badge·Button·Dialog·Input·Label·Textarea 추가·적용 완료 | 해당 UI 디자인·구현 시 필요한 컴포넌트 추가 |
| Lucide 아이콘·Radix·클래스 유틸리티 | `/links`와 shadcn/ui 컴포넌트에 적용 완료 | shadcn/ui 기반 UI 작업 시 사용 |
| Firestore 링크 저장 | 로그인 UID별 실시간 조회·추가·수정·삭제 구현 | 정렬·실제 DB 통합 검증은 후속 |
| localStorage 저장 어댑터 | 테마의 후속 제안, 아직 코드 없음; 프로필은 Firestore 저장 | 테마 저장·초기화 구현 시 |
| React 편집 상태·공유 프로필 렌더러 | React Context로 프로필·목록 링크 공유 및 프로필 편집 폼 구현 | 프로필·링크 편집·미리보기 구현 시 |
| 테마 설정·사진 처리·입력 검증 | 링크·이름·소개 검증 구현; 테마는 예정, 사진 편집은 제외 | 관련 기능 구현 시 결정 |
| Google 인증 | Firebase Auth 팝업 로그인·로그아웃, 사용자 문서 구독 구현 | 콘솔 활성화·도메인 등록·실제 OAuth 검증 필요 |
| 백엔드 API·드래그 정렬 | 미구현 | 필요 시 후속 검토 |

미선정 항목에 대해 Zustand·폼·검증·DB·인증 등의 라이브러리를 현재 사용 중이거나 사용 확정으로 기록하지 않는다. 필요가 결정되면 설치·실제 적용 상태와 함께 이 문서를 갱신한다.

- TypeScript 7은 `@typescript/native` 별칭으로 설치했다. Next.js·typescript-eslint의 API 호환을 위해 `typescript`에는 `@typescript/typescript6` 6.0.2를 별칭으로 설치한다. [Microsoft 공식 병행 설치 가이드](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/#running-side-by-side-with-typescript-6.0)를 따른다.
- Next.js의 일부 린트 플러그인은 ESLint 10에서 제거된 API를 사용하므로 `eslint.config.mjs`에 공식 `@eslint/compat`의 `fixupConfigRules`를 적용했다. 플러그인의 ESLint 지원 범위에 따른 npm peer 경고는 남아 있다.
- `npm audit`는 shadcn·Next.js 린트 도구의 간접 의존성 경로에서 high 경고 9건을 보고했다. 제시된 자동 수정은 shadcn·`eslint-config-next`의 이전 주 버전 설치이므로 적용하지 않았다. 최신 버전 적용과 취약점 경고 해소는 별도로 관리한다.

**완료 기준·검증 결과:** `npm outdated --json` 결과가 빈 객체이며 `npm run lint`, `npm run build`, TypeScript 7의 `tsc --noEmit --incremental false`가 모두 통과했다. 이번 작업은 의존성과 도구 호환 설정 변경이며 화면·기능 구현은 포함하지 않는다.

### 기능별 책임 — 현재 저장 처리 외 공통 모델·어댑터는 후속 설계

| 구분 | 책임 | 후속 변경 방법 |
| --- | --- | --- |
| 프로필 데이터 모델 | 이름·소개·사진·링크·테마 ID와 버전 정의 | 계정·페이지 ID, 게시본 등 필드 추가 |
| 편집 상태·동작 | 프로필 변경, 링크 CRUD·순서, 테마 선택 | 새로운 UI도 기존 동작을 호출 |
| 저장 처리 | 현재 개인 링크 구독·CRUD는 `LinksProvider`; 공통 `load/save/reset` 계약은 후속 제안 | 프로필·테마 저장과 정렬 계약 결정 |
| 프로필 렌더러 | 전달받은 데이터·테마를 화면으로 표시 | 추후 공개 페이지에서도 재사용 |
| 테마 설정 | 테마 ID와 스타일 토큰 목록 | 테마 항목·설정값 추가 |
| 입력 검증 | 이름·소개·URL·사진 제한 | 정책 값 변경, 서버 검증과 연결 |
| 사진 처리 — 제외 | 기존 Google 사진 표시만 제공 | 업로드 필요 시 별도 요구사항 결정 |
| 예시 데이터 | 최초 접속·초기화 기본값 | 샘플 내용만 교체 |

- 화면 컴포넌트가 localStorage를 직접 읽고 쓰지 않는다. 저장 어댑터를 통해 처리한다.
- 저장 계약은 비동기 호출 형태로 정의해 향후 서버 요청을 연결할 수 있게 한다. 현재 링크는 Firebase SDK의 비동기 쓰기·구독을 사용한다. 공통 `load/save/reset` 저장 어댑터는 아직 없다.
- 이름 길이·사진 용량 등 제한은 한곳의 설정값으로 관리한다.
- 링크 ID는 내용·순서와 독립적이다. 수정과 이동 시 새 ID를 만들지 않는다.
- 데이터는 직렬화 가능한 형태로 관리하며 `schemaVersion`을 포함한다. 저장 키는 `mylink.profile`처럼 앱 전용 이름을 사용한다.
- 저장 데이터는 읽을 때 구조와 값의 유효성을 검증한다. 스키마 변경 시 이전 버전 마이그레이션 함수를 추가할 수 있게 한다.
- 비밀키·인증 토큰·개인 계정 정보는 저장 데이터에 포함하지 않는다.

### 프로필·테마 통합 저장 데이터 예시 — 후속 제안

아래 JSON은 향후 통합 모델이며 현재 Firestore 문서 구조가 아니다. 현재는 `links` 배열의 개별 필드에서 `id`를 제외한 본문과 `createdAt`을 링크 문서마다 저장하며 `schemaVersion`·`profile`·`themeId`는 저장하지 않는다.

```json
{
  "schemaVersion": 1,
  "profile": {
    "name": "김마이",
    "bio": "제가 만든 것들을 소개합니다.",
    "avatar": null
  },
  "links": [
    {
      "id": "link-unique-id",
      "title": "포트폴리오",
      "description": "직접 만든 프로젝트와 작업물을 소개해요.",
      "url": "https://example.com/portfolio",
      "icon": "FolderOpen",
      "category": "portfolio",
      "actionText": "작업 보기",
      "isExternal": true,
      "badge": "추천",
      "displayOrder": 1
    }
  ],
  "themeId": "minimal"
}
```

`avatar`는 이번 버전에서 `null` 또는 변환된 이미지 data URL이다. 향후 서버 저장 시 이미지 파일 참조로 변경할 수 있다. 링크 순서는 `displayOrder`로 표현하고 저장 배열도 같은 오름차순으로 유지한다.

## 7. 예외 처리·품질 기준

링크 조회 실패·저장 실패·저장 중 중복 제출 방지는 현재 구현했다. 아래 사진·브라우저 저장·손상 데이터 처리 등은 해당 기능 구현 후 충족할 목표다.

| 상황 | 처리 |
| --- | --- |
| 잘못된 URL·빈 제목 | 해당 입력에 오류 표시, 확정 방지 |
| 사진 읽기·변환 실패 | 이전 사진 유지, 오류 표시 |
| Firestore 링크 조회 실패 | 오류와 새로고침 안내, 추가 버튼 비활성화 |
| Firestore 링크 저장 실패 | 폼 입력 유지, 오류 표시, 재제출 허용 |
| Firestore 링크 저장 대기 | 저장 중 표시, 입력·중복 제출·닫기 방지; 오프라인 타임아웃은 미구현 |
| 브라우저 저장 차단·용량 초과 | 입력 유지, 저장 실패·재시도 표시 |
| 저장 데이터 손상 | 오류 안내와 예시 화면, 확인 전 원본 자동 덮어쓰기 금지 |
| 알 수 없는 테마 | 기본 테마 사용 |
| 링크 없음 | 빈 상태 문구 표시 |
| 이미지 표시 실패 | 기본 아바타로 대체 |
| 스크립트 텍스트 | 일반 텍스트로 표시 |
| 360·768·1,440px 화면 | 가로 넘침 없이 편집·보기 가능 |
| 키보드 조작 | 입력 라벨, 포커스 표시, 버튼 조작·링크 순서 이동 가능 |
| 터치 조작 | 주요 버튼 터치 영역 44×44px 이상 제안 |

localStorage는 브라우저 데이터 삭제·비공개 모드 종료 등에 따라 사라질 수 있다. 이 제약은 후속 브라우저 프로필·테마 저장에 대한 설명이다. 현재 링크는 같은 Firebase 프로젝트에서 로그인한 계정의 개인 데이터를 조회한다. 동일 계정의 개인 링크 조회는 구현했으며 백업·복구·파일 내보내기·가져오기는 미구현이다.

## 10. 후속 확장 항목

| 확장 | 추가 작업 |
| --- | --- |
| 인증·서버 검증 강화 | Google 로그인·계정별 경로는 구현; 실제 규칙 검증·서버 필드 검증 강화 검토 |
| 개인 공개 주소 확장 | 표시 이름 기반 주소 구현; 별도 고정 아이디·주소 변경 이력 정책은 후속 |
| 게시·공개 중지 | 초안·게시본 분리, 게시 상태·캐시 정책 |
| 주소·QR 공유 | 실제 공개 URL 생성 후 복사·QR 기능 연결 |
| 더 풍부한 꾸미기 | 테마 항목 추가, 커스텀 색상·사진 자르기 |
| 링크 편집 편의 | 드래그 정렬, 숨김, 삭제 실행 취소 |

이번 설계는 화면과 저장 처리의 결합을 줄이기 위한 것이다. 추가 인증 방식·공개 게시를 도입할 때는 데이터 모델과 제품 정책도 확장해야 하며, 저장 어댑터 교체만으로 모든 후속 기능이 완성되지는 않는다.
